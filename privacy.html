Política de Privacidad de Creator Finder

Cómo una aplicación privada y local de XOTOX STUDIO accede, utiliza, almacena y protege la información necesaria para su funcionamiento.

Resumen y alcance

Esta política se aplica a Creator Finder, una aplicación de escritorio/local creada y utilizada actualmente por su desarrollador para gestionar campañas de videojuegos. También describe este sitio web estático.

Este sitio no recopila datos.La web no incluye cuentas, formularios, analítica, publicidad ni cookies de seguimiento. El selector de idioma solo guarda una preferencia temporal en el almacenamiento de sesión del navegador y no la transmite. Los enlaces externos se abren en los servicios correspondientes.

2. Qué es Creator Finder

Creator Finder es una aplicación privada y local para descubrir creadores, analizar su relevancia para campañas de videojuegos, organizar candidatos, registrar vías de contacto profesionales y gestionar outreach. No es un servicio SaaS y no ofrece acceso público.

La aplicación utiliza YouTube Data API v3 para consultar información pública y puede usar Gmail OAuth cuando el usuario conecta voluntariamente su propia cuenta de Google.

4. YouTube Data API Services

Creator Finder usa YouTube Data API Services para consultar información pública necesaria para descubrir y evaluar canales y vídeos relacionados con campañas de videojuegos.

  • No vende datos obtenidos mediante YouTube API.
  • No proporciona a terceros acceso a YouTube API Data.
  • No intenta evitar ni eludir las cuotas de YouTube API.
  • Utiliza caché, deduplicación, batching cuando corresponde, presupuestos de cuota y reutilización de información para reducir solicitudes redundantes.

Creator Finder aplica conservadoramente una antigüedad máxima de 30 días a los datos no autorizados obtenidos mediante YouTube Data API. Antes de mostrarlos o utilizarlos, los datos caducados se intentan actualizar mediante el endpoint oficial apropiado; si no pueden actualizarse —incluida la falta de cuota— se invalidan o eliminan y no se usan como actuales. El historial propio de campañas, notas, decisiones y marcas de no contactar permanece separado mediante procedencia e IDs internos.

La compilación baseline no extrae emails desde descripciones, comentarios, chat ni páginas de YouTube y no hace scraping de YouTube o Google. El descubrimiento de contactos se limita a entradas manuales y páginas web externas públicas enlazadas legítimamente por el creador.

5. Gmail y autorización del usuario

Gmail OAuth se utiliza únicamente cuando el usuario decide conectar su cuenta de Google. La autorización es incremental y contextual:

  • https://www.googleapis.com/auth/gmail.compose: buscar y consultar metadatos mínimos de borradores, crear borradores y enviar el borrador o mensaje que el usuario haya aprobado de forma explícita;
  • https://www.googleapis.com/auth/gmail.readonly: leer un thread de Gmail cuyo ID ya está asociado localmente a un mensaje de campaña, con el fin de comprobar si existe una respuesta y registrar sus datos para el seguimiento.

gmail.compose se solicita al conectar borradores/envío. gmail.readonly no se solicita por adelantado: solo cuando el usuario activa expresamente la detección de respuestas. Sin gmail.readonly, borradores y envío siguen disponibles y la lectura queda desactivada. La comprobación se limita a threads de campaña ya conocidos; no realiza una búsqueda general del buzón, no marca mensajes como leídos, no mueve mensajes y no modifica labels. Creator Finder no vende contenido de Gmail, no lo utiliza para publicidad de terceros y no lo comparte con terceros.

6. Datos obtenidos mediante Google APIs — Limited Use

El acceso, uso, almacenamiento y transferencia de información recibida mediante los scopes de Google Workspace se limita a proporcionar las funciones visibles de Creator Finder descritas en esta política: preparación, envío aprobado y seguimiento de comunicaciones de campaña.

The use of information received from Google Workspace scopes will adhere to the Google User Data Policy, including the Limited Use requirements.

La declaración anterior sigue el ejemplo de disclosure publicado en la Google Workspace API User Data and Developer Policy. Creator Finder no usa datos de Gmail para crear, entrenar o mejorar modelos de inteligencia artificial generalizados.

7. Datos almacenados y conservación

Creator Finder almacena principalmente datos en el dispositivo local donde se ejecuta. Puede conservar una base de datos y archivos de aplicación necesarios para:

  • caché y reducción de consultas repetidas;
  • deduplicación y marcas de no contactar;
  • campañas, señales internas de relevancia y decisiones de revisión;
  • historial operativo, contactos, emails y estados de outreach;
  • mantener la autorización de la cuenta conectada mientras siga vigente.

Los registros operativos locales se conservan mientras sean necesarios para el funcionamiento, el historial de campaña y la prevención de duplicados, salvo que una política aplicable exija un periodo menor. YouTube API Data se actualiza o invalida/elimina como máximo a los 30 días y nunca se mantiene visible como actual una vez caducado. Los datos locales obtenidos mediante Gmail se conservan hasta que dejen de ser necesarios o el usuario use el control de desconexión y eliminación.

Separación y procedencia.La base local clasifica datos como YOUTUBE_API, GOOGLE_GMAIL, PUBLIC_WEB, USER_ENTERED o APPLICATION_GENERATED. La expiración de YouTube API Data no borra accidentalmente campañas ni decisiones propias.

8. Base del tratamiento y derechos aplicables

Creator Finder trata la información necesaria para las funciones solicitadas por su usuario y para el interés legítimo del desarrollador en identificar colaboradores profesionales relevantes para sus propias campañas, siempre sujeto a una evaluación adecuada, a la legislación aplicable y al derecho de oposición. La autorización OAuth permite el acceso técnico a Google; no sustituye otros requisitos legales que puedan resultar aplicables.

Cuando la normativa de protección de datos lo reconozca, una persona puede solicitar acceso, rectificación, eliminación, limitación u oponerse al tratamiento de información que le concierna. Las solicitudes pueden enviarse a xotoxoficial@gmail.com. También puede presentarse una reclamación ante la autoridad de protección de datos competente.

9. Control, revocación y eliminación

Revocar acceso a Google

El usuario puede revisar o revocar el acceso concedido a Creator Finder desde la configuración de conexiones de su cuenta de Google.

Eliminación y consultas de privacidad

En Configuración → Privacidad y cumplimiento, el usuario puede revocar el token con el endpoint oficial de Google, eliminar token.json y borrar metadatos y respuestas locales obtenidos mediante Gmail sin eliminar el archivo de credenciales OAuth del desarrollador. También puede eliminar todos los datos asociados a un creador mediante su creator_internal_id; esto elimina datos de Creator Finder, no información existente en YouTube.

Para solicitar ayuda o realizar una consulta relacionada con privacidad, escribe a xotoxoficial@gmail.com.

Contactos públicos y no contactar

Si un creador o representante desea plantear una corrección o solicitar que no se utilice una vía de contacto pública, puede escribir al mismo email. Creator Finder mantiene estados para respetar decisiones de no contactar y evitar duplicados.

2. What Creator Finder is

The application uses YouTube Data API v3 to query public information and may use Gmail OAuth when the user voluntarily connects their own Google account.

4. YouTube Data API Services

Creator Finder uses YouTube Data API Services to query public information needed to discover and evaluate channels and videos related to videogame campaigns.

  • It does not sell data obtained through the YouTube API.
  • It does not give third parties access to YouTube API Data.
  • It does not attempt to avoid or circumvent YouTube API quotas.
  • It uses caching, deduplication, batching where appropriate, quota budgets, and information reuse to reduce redundant requests.

Creator Finder conservatively applies a maximum age of 30 days to non-authorized YouTube API Data. Before display or use, expired data is refreshed through the appropriate official endpoint; if refresh is unavailable, including because quota is exhausted, the data is invalidated or deleted and is not used as current. Campaign history, notes, user decisions, and do-not-contact state are separated through provenance and internal identifiers.

The baseline build does not extract emails from YouTube descriptions, comments, chat, or YouTube pages and does not scrape YouTube or Google. Contact discovery is limited to manual entries and external public websites legitimately linked by the creator.

5. Gmail and user authorization

Gmail OAuth is used only when the user chooses to connect a Google account. Authorization is incremental and contextual:

  • https://www.googleapis.com/auth/gmail.compose: find and retrieve minimal draft metadata, create drafts, and send the draft or message expressly approved by the user;
  • https://www.googleapis.com/auth/gmail.readonly: read a Gmail thread whose ID is already associated locally with a campaign message, in order to check for a reply and record its follow-up data.

gmail.compose is requested when draft/send is connected. gmail.readonly is requested separately only when the user explicitly activates reply tracking. Without read-only access, drafts and sending remain available while reply reading stays disabled. Checks are limited to known campaign threads; Creator Finder does not search the general mailbox, mark messages read, move messages, or modify labels. Creator Finder does not sell Gmail content, use it for third-party advertising, or share it with third parties.

6. Data obtained through Google APIs — Limited Use

Access, use, storage, and transfer of information received through Google Workspace scopes is limited to providing the visible Creator Finder features described in this policy: preparation, approved sending, and follow-up of campaign communications.

The use of information received from Google Workspace scopes will adhere to the Google User Data Policy, including the Limited Use requirements.

The statement above follows the disclosure example published in the Google Workspace API User Data and Developer Policy. Creator Finder does not use Gmail data to create, train, or improve generalized artificial intelligence models.

7. Stored data and retention

Creator Finder stores data primarily on the device where it runs. It may retain a database and application files needed for caching, duplicate prevention, do-not-contact flags, campaigns, internal relevance signals, review decisions, operational history, contacts, emails, outreach states, and active account authorization.

Local operational records are kept while needed for application functionality, campaign history, and duplicate prevention unless an applicable policy requires a shorter period. YouTube API Data is refreshed or invalidated/deleted no later than 30 days and is never presented as current after expiry. Local data obtained through Gmail is retained until no longer needed or until the user uses the disconnect-and-delete control.

Separation and provenance.The local database classifies data as YOUTUBE_API, GOOGLE_GMAIL, PUBLIC_WEB, USER_ENTERED, or APPLICATION_GENERATED. YouTube API Data expiry does not accidentally erase campaigns or user decisions.

8. Processing basis and applicable rights

Creator Finder processes information needed for user-requested features and for the developer's legitimate interest in identifying relevant professional collaborators for its own campaigns, always subject to an appropriate assessment, applicable law, and the right to object. OAuth authorization enables technical access to Google; it does not replace any other legal requirement that may apply.

Where recognized by applicable data protection law, a person may request access, correction, deletion, restriction, or object to processing of information concerning them. Requests may be sent to xotoxoficial@gmail.com. A complaint may also be submitted to the competent data protection authority.

9. Control, revocation, and deletion

Revoke Google access

The user can review or revoke Creator Finder's access through their Google Account connections settings.

Deletion and privacy questions

Under Settings → Privacy and compliance, the user can revoke the token through Google's official endpoint, delete token.json, and erase locally stored Gmail-derived metadata and replies without deleting the developer OAuth client file. The user can also erase all stored data for one creator by creator_internal_id; this removes Creator Finder data, not information held by YouTube.

For deletion assistance or privacy questions, email xotoxoficial@gmail.com.

Public contacts and do-not-contact requests

A creator or representative may use the same email to request a correction or ask that a public contact route not be used. Creator Finder maintains states intended to respect do-not-contact decisions and prevent duplicates.
